# The gap intake of 21.09.2026

**Owner, 21.09.2026:** *"172 series … those unrecorded certificates, you have to assign
everything that's needed. Everything, everything, everything in full, and I will decide if
I will issue them or not."* And: *"Lift any parameter results; empty results should not be
included. There should be no 'not tested' results in the retest CoQs."*

## The premise was wrong, and that mattered

Eighty-one cells on Batch Coverage carried `○` — *on file 09.09, not recorded*. The mark
is painted from the static `coverage_update_2026-09-09.tsv` onto any cell not already `✓`
(`tracker/build_tracker_v8.py:2239-2258`), and it had been read as eighty-one documents
nobody had taken in.

Fifty-one of them had been taken in. The intakes of **16.09.2026** (the IJZ-MB campaign
microbiology) and **18.09.2026** (sixty-five contaminant panels of the Institute of Public
Health) wrote their results into `coq_artifact_data.json` and the release register — what
the certificates print — and never into `tracker/new_instances.json`, the tracker's own
document pool (`build_tracker_v8.py:277-279`). Two records, one intake path. So the
tracker never credited documents that were already the cited source on the face of the
certificate, and the 09.09 overlay kept painting over them.

`tracker/new_instances_from_artifact.py` registers every document that the overlay names,
a certificate cites, and the manifest does not carry — fifty-one of them, values taken
verbatim from the row the certificate prints, which had already passed its own intake's
gate. **○ fell from 81 to 6.**

## The gate

Two independent vendors, never the same engine twice: read A on OpenAI's model, read B on
Google's, each reading the rendered page without seeing the other's answer
(`two_reads.py`). A value is taken only where both wrote the same thing, compared on the
printed string — `< 10`, `< 10² и > 10` and `Отсутна` are three different assertions.

    documents read twice   7
    values agreed          33
    settled by a third read 5
    held                   0

**Three disagreements, all settled by the desk reading the page itself** (`reads_C.json`,
each with the region it was cut from):

* `402/0785/26`, bile-tolerant gram-negative — read A stopped at `< 10²`, read B carried
  `< 10² и > 10 CFU/g`. The page carries the full range. **The fuller read was right
  again** — the fifth instance of the OI-36 class, after the four settled the same way on
  16.09.2026.
* `433/0847/26`, the lot — read A gave `FBD32601`, the zero read as a Latin D. The page
  prints `FB032601`, and so do the scan's file name and the 09.09 update.
* `031-3-К/26` — read B raised three identification rows out of the report's *title*.
  The result table has three rows and they are the three cannabinoids. A title is not a
  determination; read A was right. What the report does certify for #3 is the desk's
  standing rule for a Farmahem cannabinoid report, which its siblings `031-2`, `031-4` and
  `031-5-К/26` already carry.
